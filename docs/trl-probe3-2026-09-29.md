# Trade-press feed probe 3 — 2026-09-29

The Nexis hand count (`docs/nexis-hand-count-verdict-2026-09-29.md`) found
pilot-stage news in volume, but only 3 of 12 trade titles in Nexis, and its
hits came from aggregators. This probe asks the question one step closer to
the source: **do the trade titles' own public feeds permit reading, and do
they carry pilot-stage news often enough to collect?** Sixteen titles:
the twelve from the Nexis source check, plus Supply Chain Brain, Material
Handling & Logistics, The Robot Report and Trucking Dive. Script:
`docs/experiments/trl/probe3.py`. Raw responses: `data/trl/probe3/`
(gitignored, not committed). No model calls.

**Order of work.** Permission first: for each title, `/robots.txt`,
`/.well-known/tdmrep.json`, the homepage (only to find the footer's legal
links and the `<link rel="alternate">` feed), then the terms pages. The
permission calls below were made by hand from those saved files and written
into the script (`CALLS`) **before any feed was fetched**. Content second:
only green and amber titles' feeds, and only the feed. **No article page was
fetched for any title in the content phase** (see Concerns for four pages
fetched by mistake during discovery). Every host got one request every 2 s,
or its robots `Crawl-delay` if longer (from the second run on; see Concerns).
A 403, challenge or non-feed answer was recorded and not retried with other
headers. **But every refusal was requested twice**: the script's `get()`
re-sent the same request once to capture the refusal's body, so each 404
cost two requests and Commercial Carrier Journal's challenged host received
six (robots.txt, tdmrep and homepage, twice each). The script now records a
refusal from the first response (status only; `http.HttpError` carries no
body); the saved CCJ envelopes hold the body of the second request.

This report quotes terms of use to classify them. **It is not legal
advice**; where terms are ambiguous the title is amber and the question is
put to the owner.

## Run

```
SEC_CONTACT_EMAIL=<contact> python docs/experiments/trl/probe3.py --phase all
```

Every response is saved as a JSON envelope (URL, final URL, status, time,
body) and reused unless `--refresh`. The hand counts are in the script
(`HAND`, keyed by the start of each item's title); a run resolves each one
against the saved feed and stops if an item is missing, so every count below
traces to a saved file (`data/trl/probe3/hand.json`).

## What the owner must decide (amber titles)

For each amber title the question is the same: **does a program that reads
the publisher's public RSS feed once a day, matches headlines and summaries,
and publishes counts with headline links fall inside the terms' prohibitions
("data mining, robots", "any robot … for any purpose, including monitoring",
"personal use only", "stored in any retrieval system", "data mine or scrape …
using automated means")?** The feeds are offered to readers and read by
programs (feed readers) by design; the terms do not mention RSS (except JOC's
RSS page, which invites "a news reader"). The options: (a) treat a public feed
as licensed for this use; (b) write to the publisher and ask (Informa
TechTarget for Supply Chain Dive and Trucking Dive; FreightWaves; ATA for
Transport Topics); (c) leave amber titles out. Two narrower rulings:

- **Storage.** Collectors keep the raw response. For FreightWaves (full text
  in the feed) that is an archive of articles; Endeavor (MH&L) forbids
  caching or archiving outright. If amber feeds are read, decide whether raw
  is kept, or only title, date, link and match.
- **Model use.** The observatory's TRL extraction sends document text to a
  model. DC Velocity blocks ClaudeBot, GPTBot and other AI crawlers; MMH
  declares `ai-train=no` and `use=reference` and blocks the same crawlers;
  Logistics Management blocks GPTBot. Supply Chain Dive's and Trucking Dive's
  own robots.txt files name no GPTBot, ClaudeBot or anthropic-ai group, but
  their parent's file (www.industrydive.com/robots.txt) gives `Disallow: /`
  to GPTBot, ChatGPT-User, Google-Extended, PerplexityBot, ClaudeBot,

## Concerns

- **Four pages were fetched that should not have been**, all in the first
  permission run, by an anchor-text heuristic, before the terms pages were
  chosen by hand: two SCMR article pages ("AI and Contracts: Shifting Insight
  Beyond Legal", taken as a legal link because its anchor text contained
  "Legal"); FreightWaves' "Legal issues" news category listing (20 article
  cards; FreightWaves is amber, so only its feed was allowed); and one
  Loadstar tag page (`/tag/premium-legal-insight/`), which Loadstar's
  robots.txt disallows. The saved files were deleted; nothing was used from
  them (the FreightWaves file was deleted unread). The Loadstar fetch passed
  the robots check because of a defect, below.
- **`urllib.robotparser` misreads robots.txt files in three ways seen here.**
  It takes the first matching line, not the longest; it reads an empty
  `Disallow:` as "allow everything" (The Loadstar: it allows `/tag/`); and it
  uses only the first `User-agent: *` group, so a broad `Allow: /` in an
  earlier group or a second `*` group is ignored. On the saved files it allows
  joc.com/search, joc.com/user/profile and mmh.com/member/x, all of which RFC
  9309 longest-match over every `*` group disallows. The probe now requires
  both (`rfc9309_allows`); an audit of every saved request found no other
  disallowed path. **`observatory/collectors/pressroom.py` (`robots_allows`),
  which runs in the weekly cron, inherits all of this.** The fix is an RFC
  9309 longest-match parser that merges every group for the agent.
- **Crawl-delay was not honoured in the first permission run**: robots.txt,
  tdmrep and homepage requests went to Supply Chain Dive, Trucking Dive
  (5 s), Logistics Management, SCMR (20 s), Supply Chain Brain and The Robot
  Report (10 s) at 2 s intervals, three or four requests each. mmh.com's
  second `User-agent: *` group sets `Crawl-delay: 20`, and it received three
  requests within 6 seconds (robots.txt, tdmrep, homepage). Endeavor
  (`Crawl-delay: 3`) had its robots.txt and the MH&L terms page fetched in the
  same second. From the second run the limiter takes the larger of 2 s and
  the host's delay.
- **Collector defects these feeds expose**, all in `pressroom.py` if it reads
  them: Transport Topics' `pubDate` uses a two-digit year ("Tue, 29 Sep 26
  11:47:15 EDT"), which `parse_date` returns as None, so every item would be
  undated and dropped; Industry Dive escapes the HTML in its descriptions, so
  one `visible_text` pass leaves tag text in the summary (the probe runs it
  twice); The Robot Report's `Crawl-delay` sits above the first `User-agent`
  line, where robotparser ignores it.
- **Feedburner.** `feeds.feedburner.com/robots.txt` returns an HTML redirect,
  not a robots file; two of the three Peerless Feedburner feeds are stale.
  The owner may want to ask Peerless whether those feeds are retired.
- **One reader.** All hand counts are mine, from title and summary, with no
  second reader; borderline items are listed above. The any-technology
  count's boundary ("a supply chain technology", excluding mature equipment
  such as trailers and lithium-ion forklifts) is a judgment.
- **Paywall column** is read from homepage markers (paywall scripts,
  "Subscribe", premium paths), not from article pages, which were not
  fetched.
- **Industry Dive feeds are 10 items**; at Supply Chain Dive's pace that is
  under a week, so even a daily poll must not miss a day.
